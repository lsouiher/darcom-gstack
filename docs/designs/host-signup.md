## Vision

### Context
The /office-hours design doc already did the deep scope work and locked in Approach B
(Full host funnel). This CEO review did not relitigate the approach — it held the
scope as baseline and surfaced discrete cherry-pick expansions, each opt-in by the user.

### Platonic Ideal (12-month)
A host in Cairo or Lagos clicks a founder-shared WhatsApp message, sees a landing page
that speaks their language and market, taps "Become a host," verifies via WhatsApp OTP
in 10 seconds, lists a property in under 5 minutes, and collects their first rent
without chasing a tenant. Another host sees theirs succeed, asks how, gets a referral
link, signs up — the supply side compounds on itself.

This plan is the door to that vision. It doesn't build the referral loop (deferred to
TODOS.md), the WhatsApp bot (Approach C, later), or the ownership-verification flow
(required before international expansion). It makes the door work.

## Acknowledged Tension

**#3 (resume-link email) vs D2 (defer pre-wizard email capture).** Not contradictory but worth
naming: #3 only sends email AFTER step 2 (email is already captured inside the wizard), so we
don't need a landing-page email capture to make #3 work. D2 stays deferred. If we later
accept D2, the two flows share the same transactional-email infrastructure added by #3.

## Risks

- **WhatsApp OTP dependency on Meta Business API** — outages happen and template approval
  is non-trivial. SMS fallback (cherry-pick #2) covers this; but if both channels are down,
  signup is broken. Mitigation: `DW_SIGNUP_PUBLIC_ENABLED` kill switch (#13) + graceful
  error copy.
- **Twilio cost surprise from high-attempt OTP attacks** — country allow-list + rate
  limiter contain this, but set a Twilio spending alert as ops hygiene (not a code task).
- **PostHog vendor lock-in** — analytics wrapper in `services/analytics.ts` is the seam;
  swap cost is bounded if we keep the call surface minimal.
- **"Fire-and-forget" side effects hide failures** — Slack alert, analytics, audit-write
  failures are all non-fatal to signup. Compensating control: local WARN log on each
  failure path, plus the 2 alerts in #12c.
- **Resume-link email deliverability in target geos** — Gmail delivery to MENA/LatAm hosts
  is usually fine; Yahoo Mail and ISP-provided inboxes in some regions can reject
  unauthenticated senders. Ensure SPF/DKIM on the sending domain before launch.
